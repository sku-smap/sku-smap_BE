# 경로 조회 API

요청·응답 필드, 오류 코드, 호출 예시는 [API.md](API.md)를 참고한다. 아래는 탐색 정책 요약이다.

`POST /api/v1/routes`

```json
{
  "fromNodeId": "bus_stop",
  "toNodeId": "eunju2_men"
}
```

현재 DB의 노드와 방향 간선을 조회하여 다익스트라로 계산한다. 요청에 단일 `option`을 추가할 수 있으며 생략하거나 null이면 `OUTDOOR_FIRST`이다.

| option | 조건 | 비용 |
|---|---|---|
| OUTDOOR_FIRST | 야외경로 우선·기본값 | 기본 1 + 실내·지하 끝점마다 1 |
| COMFORTABLE | 편한길 | 기본 1 + 계단 5 + 야외·지하 끝점마다 1 |
| SHORTEST | 최단거리 | 모든 간선 1 |
| INDOOR_UNDERGROUND_FIRST | 실내지하우선 | 기본 1 + 야외 끝점마다 1 |

예: `"option": "SHORTEST"`. 공간 비용은 양 끝점이 비선호 공간이면 +2, 출입 전환이면 +1이다. 실내와 지하는 실내지하우선에서 동등하게 취급한다. 지하층은 편한길에서는 야외로 분류하여 같은 공간 추가 비용을 적용한다. 편한길의 야외 계단은 기본 1 + 야외 2 + 계단 5로 비용 8이다. 계단을 금지하지 않으며 경사도·거리·시간은 추정하지 않는다. 잘못된 option 또는 여러 조건의 배열은 입력 오류이다.

공간은 현재 노드의 건물·층·사진명과 확인한 외부 출입구 목록으로 판단한다. 분류가 불명확한 경우에는 공간 추가 비용을 주지 않는다. 실제 위치와 다른 메타데이터가 있으면 검수·보완이 필요하다.

공통 응답의 `data.nodes`는 이동 순서대로 정렬된 노드와 원본 사진 파일명이며 각 노드의 `imageUrl`에는 비공개 S3 사진을 조회하는 임시 URL을 반환한다. `data.segments`는 구간별 출발·도착 ID, 이동 유형과 안내 문구이다. `data.totalSteps`는 간선 수이며 선호 추가 비용을 포함하지 않는다. 시간은 제공하지 않는다. 사진 설정과 AWS 권한은 S3-PHOTOS.md를 참고한다.

출발과 도착이 같으면 노드 한 개, 빈 구간 목록, 이동 횟수 0을 반환한다. 없는 노드는 `ROUTE_404_NODE`, 방향상 도달할 수 없는 경로는 `ROUTE_404_PATH` 오류로 반환한다.

원본에 없는 역방향 간선은 생성하지 않는다. 원본의 빈 이동 유형은 응답에서 null로 유지하며 계단으로 추정하지 않는다. 공간 조건의 비용은 동일하게 반영한다.

각 `data.nodes` 항목의 `description`은 현재 노드에서 다음 노드로 이동하는 구간의 안내 문구이다. 마지막 도착 노드는 다음 구간이 없어 null이다. `places`는 `places.arrive_node_id`가 해당 노드 ID와 일치하는 장소 목록이며, 매핑된 장소가 없으면 빈 배열이다. 장소는 이름과 ID 순서로 정렬한다. 장소별 ID, 이름, 분류, 건물, 층, 호실, 도착 노드 ID와 이름, 출입문 사진, 별명, 부가 설명을 제공한다.

같은 건물에서 연속되는 엘리베이터 이동은 응답의 segments에서 실제 승차·하차 노드를 잇는 하나의 구간으로 묶는다. 예: L층→9층→10층은 L층→10층 구간과 `엘리베이터를 타고 L층에서 10층으로 이동합니다.` 안내로 반환한다. 도착 후 도보 구간은 별도로 유지한다. 이는 화면용 요약이며 DB에 직접 연결 간선을 생성하지 않는다.

nodes의 원본 노드·사진·장소 목록은 유지하며 승차 노드에 통합 안내를 표시하고 중간 엘리베이터 노드의 description은 null이다. totalSteps는 통합 전 실제 간선 수이므로 segments의 길이와 다를 수 있다. 원본 경로·탐색 비용·DB 안내는 변경하지 않는다. 도보 환승·건물 변경·층 정보 누락·판단 가능한 상승/하강 방향 전환에서는 합치지 않는다.
